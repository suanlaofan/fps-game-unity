|---|---|

| 恢复疾跑 | 步行 2.0 m/s，疾跑 3.6 m/s；左摇杆按下切换，或按住左 X；暂停、追踪丢失清除疾跑 |

## 操作

| 操作 | PICO 手柄 | 当前原生 PICO 模拟器 |
|---|---|---|
| 移动 | 左摇杆 | WASD |
| 射击 / 菜单点击 | 右扳机 | U |
| 手动换弹 | 右 B 或右 Grip | O（右 Grip）；Forward Delete 对应右 B |
| 切换疾跑 | 按下左摇杆 | R |
| 按住疾跑 | 左 X | X |
| 暂停 / 恢复 | 右 A | Space |
| 分段转向 | 右摇杆左右 | J / L |

模拟器先启用左侧蓝色手柄模式，并聚焦模拟器窗口。Mac 普通 Delete 是退格键，未必发送 Forward Delete，优先使用 O 换弹。底部选择“右手柄模式”和手柄 Interaction 工具；不按修饰键移动鼠标调整射线，再按下并松开 U。近处 UI 存在视差，以按钮响应为准。Shift+WASD 会平移当前手柄，Shift+Q/E 降低/抬高手柄；原生模拟器疾跑应使用 R/X。Option+左键拖动用于相机环绕。

Unity Editor 预览键位与原生模拟器不同：WASD移动，Shift/X按住疾跑，左Ctrl切换疾跑，U射击，R/O换弹，Q/E转向，Esc暂停。Android 不使用 Editor 键盘分支。

## 构建与诊断

版本 `1.2.3-vr-feedback` / code15，包名 `com.suanlaofan.fpsgame.picofresh`。APK输出 `Builds/PICO/Level0-PICO-VR-v1.2.3.apk`。旧v1.2.0、v1.2.1、v1.2.2 APK保留；v1.2.1与v1.2.2的原生菜单仍有镜像裁切，本次以v1.2.3为准。

完整构建入口：`PicoFreshBuild.ConfigureAndBuild`。顺序为场景设置、灯光优化、创建bootstrap、联合遮挡烘焙、重新生成玩法Bundle、原生Android APK。只烘焙jogo或重新创建bootstrap后不烘焙，会破坏这套联合数据。Unity MCP中BuildPlayer受玩家循环限制，保存并关闭本工程Editor后用Unity原生batchmode执行上述入口。

运行时每5秒写 `level0-performance.csv` 与 `LEVEL0_PERF` 日志。`focused`/`focus_changes`记录 Android 应用焦点；它无法单独识别宿主 macOS 模拟器被遮挡或失焦产生的节流。本次存在应用仍报告 focused=1、原生窗口置前后帧率恢复的低帧区间，必须结合宿主窗口状态解释。FPS/P95/P99来自该窗口；CPU/GPU列为最后可用帧，不是窗口百分位值。通过 `LEVEL0_INPUT_RELOAD`、`LEVEL0_INPUT_SPRINT` 区分真正PICO手柄输入与Editor事件。真实头显的实体追踪、双眼舒适性及持续热稳定帧率需要在该设备测试。

扳机定位的原始网格测量、正常握持和侧看完整枪身的Editor实景截图见 `Evidence/v1.2.3/weapon-trigger-grip-verification.json` 及对应图片。真实扳机参考点为模型局部 `(0,-0.01266,0.16069)`，并非枪托。

APK大小207,520,046 bytes，SHA256 `42198f7f7832b4f4f069a755d5cc68acfd55672eb2a653eafc3e28dd067b0d86`。ARM64、v2签名、16KiB对齐、ZIP完整性、内置Bundle与源文件字节一致性均通过；emulator-5554设备上base.apk摘要与交付包一致。
